## 1. 目的と探索方式・予算

- **目的**: AlgoForge 形式（`algoforge_v1`）の Strategy JSON を Candidate Generator の探索空間へ開放し、25候補の小規模探索で「生成 $\to$ 検証 $\to$ 重複排除 $\to$ 評価 $\to$ Registry 保存 $\to$ Capability Request 記録」の一連の動作を確認する（収益性改善は成功条件としない）。
- **探索方式**: 固定シード（`seed=42`）による **ローカル進化的探索（`AlgoForgeEvoGenerator`、API コスト `$0.00 USD`）**。
- **評価予算**: **25候補**（20〜30候補以内。うち 3件は意図的に未対応 `exit` / `risk` / 条件を含め、明示的拒否と Capability Request 保存を検証）。
- **root cap 制約**: 親系列上限（3件/系列）を適用し、親候補枯渇時も制約を暗黙に緩和しない（上限到達時は新規ランダム生成へ切替）。

---

## 2. 生成空間と未対応機能の扱い

- **指標**: `ema`, `sma`, `rsi`, `bb`, `donchian`, `macd`, `adx`, `stochastic`, `roc`
- **条件**: 単純比較（`>`, `<`, `>=`, `<=`, `==`, `!=`）＋ `and` / `or` 論理（入れ子論理式含む）
- **Risk**: `k_sl`, `k_tp`, `max_hold_bars` のみ
- **未対応機能**: 非空 `exit`、未対応 `risk`、未対応条件（`streak`, `rolling` 等）は黙って無視・置換せず明示的に拒否し、Capability Request JSON へ保存する。

---

## 3. 必須テスト項目・受入基準・停止条件

1. **ベクトル化契約テスト**: NaN・等値・ウォームアップ・入れ子論理式を含む戦略で、ベクトル化評価と AlgoForge 逐次 `evaluate_conditions` が **100% 一致**。
2. **因果性テスト**: 複数切断位置（ウォームアップ直後、通常区間、ギャップ境界）で未来改変不変性 **0 差分**。
3. **ハッシュ分離 & キャッシュ再利用**: 意味的に異なる戦略のハッシュ非衝突、および同一戦略の再生成時のキャッシュヒット（再実行 0回）を確認。
4. **停止条件**: 先読み検出またはベクトル化不一致が 1件でも発生した場合は即座に停止する。
